# 資料整理系統工作流程

## 系統目的
這套系統用來把外部資料逐步整理成可累積、可追溯、可回顧、可寫作的 Markdown 知識庫，並支援在 Obsidian 中閱讀、串聯與延伸。

核心路徑如下：

`inbox -> raw -> card -> opinions -> digest / outline / draft`

## 各資料夾用途
- `inbox/`：暫存尚未整理的輸入，可先放連結、片段文字、待處理清單
- `raw/`：保存盡量完整的原始內容、逐字稿、摘錄、來源資訊與缺漏說明
- `card/`：針對單筆資料建立整理卡，轉成可吸收、可引用的筆記
- `opinions/`：主題母筆記、方法論、長期觀點，負責知識沉澱與整合
- `digest/`：一段時間內的回顧、趨勢觀察、重點整理
- `outline/`：文章、簡報、教學、研究、專案的大綱
- `draft/`：正式草稿或半成品
- `rules/`：工作規則、命名規範、標籤規範、驗收標準、Obsidian 原則
- `templates/`：各類筆記的可重用模板
- `moc/`：主題導覽頁，用來整合重要卡片、母筆記與產出
- `scripts/`：必要時使用的抓取、轉檔、整理工具

## 日常處理流程
1. 先判斷資料類型與用途  
   例如文章、PDF、影片逐字稿、社群貼文、會議紀錄、隨手筆記、研究材料。

2. 建立或更新 `raw/`  
   優先保留完整內容，而不是只做摘要。至少記錄標題、來源、網址、作者、原文日期、整理日期、資料類型、完整度。

3. 建立 `card/`  
   每筆資料都建立一張整理卡，把原始內容轉成可理解、可引用、可採取行動的筆記。

4. 優先更新 `opinions/`  
   先找既有主題是否可承接這筆資料。如果可以，就更新既有母筆記；只有在沒有合適主題時才建立新主題。

5. 視累積程度產出更高層成果  
   - `digest/`：同主題或同期間資料已經出現明顯趨勢時
   - `outline/`：已經能形成清楚論點與結構時
   - `draft/`：使用者明確需要成稿，或大綱與材料已足夠時

## 貼資料後的實際執行方式
當使用者把文章、貼文、逐字稿或筆記直接貼進 Codex 後，應直接執行以下動作：

1. 以目前 workspace 為主工作區建立或更新 Markdown 檔案
2. 將原始內容寫入 `raw/`
3. 將整理後內容寫入 `card/`
4. 找出可更新的 `opinions/`，優先整合到既有主題
5. 視需要補上 `[[內部連結]]` 與 `moc/` 導覽頁

只要 Obsidian Vault 指向這個 workspace，新增或更新的 Markdown 檔案就會直接出現在 Obsidian 中，不需要再手動複製貼上。

## 何時可以自動完成
- 使用者直接貼上全文、摘錄、逐字稿或足夠完整的內容時
- 使用者提供的資料足以辨識來源、日期與用途時
- 該資料不需要額外登入或權限才能取得主要內容時

## 何時需要使用者補資料
- 只提供網址，但目前環境無法抓取全文時
- 來源內容有付費牆、登入限制或截斷
- 日期、作者或上下文不足，會影響整理品質時

遇到上述情況，應先照現有內容建立可用的 `raw` 與 `card`，同時誠實標註缺漏，不可假裝完成全文整理。

## 何時更新既有筆記
遇到以下情況，應優先更新既有 `opinions/` 或 `moc/`：
- 新資料明顯屬於既有主題
- 新資料是既有方法論的補充、修正或反例
- 新資料能讓舊觀點更完整、更具體
- 主題之間的關聯已逐漸清楚，需要補上連結與整理

## 何時建立新筆記
只有在以下情況才建立新 `opinions/` 或 MOC：
- 現有主題無法合理承接
- 新主題未來具有持續累積價值
- 建立新頁有助於降低資訊混亂，而不是增加碎片化

## 工作原則
- 先求穩定可持續，再求細緻完美
- 不可假裝取得全文；抓取不完整要誠實標示
- 摘要不可只是縮短原文，要結合使用者觀點與用途
- 優先維護既有主題，不鼓勵知識碎片化
- 整個系統以 Markdown 為主體，Obsidian 只是加強閱讀與連結的環境，不是主資料格式
